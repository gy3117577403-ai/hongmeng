# 企业微信群消息推送试用说明

## 本次接入范围

- 使用企业微信群“消息推送（原群机器人）”向机器人所在群发送消息。
- 管理员可以在系统设置中按员工编号、姓名、部门或岗位选择试发对象。
- 系统使用人事档案中的手机号尝试在群消息中提醒对应员工。
- 当前是连接试发，不会自动发送生产派工、延期或异常通知。
- 这不是企业微信单聊接口；员工不在机器人所在群内时，不能通过该方式收到群内提醒。

## 上线配置

1. 在目标企业微信群添加“消息推送（原群机器人）”。
2. 复制该机器人的完整 Webhook。
3. 在 Sealos 应用的密钥环境变量中新增：

   ```env
   WECOM_ROBOT_WEBHOOK_URL="https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=真实密钥"
   ```

4. 保存配置并重启应用。
5. 管理员登录系统，打开“系统设置 → 企业微信”，刷新连接状态。

## 小范围试发

1. 先确认测试员工满足以下条件：
   - 人事档案为在职状态；
   - 已填写手机号；
   - 通知未暂停；
   - 人事档案手机号与企业微信通讯录手机号一致；
   - 员工已加入机器人所在群。
2. 在试发页面搜索并选择 1～3 名员工。
3. 核对消息预览，勾选“我确认发送真实测试消息”。
4. 点击“发送测试”，到目标企业微信群确认：
   - 群里只出现 1 条连接测试消息；
   - 选择的员工被正确提醒；
   - 未选择员工没有被误提醒。

## 结果判断

- 页面提示“企业微信已接收测试消息”：接口已接受消息，但仍需人工确认群内实际显示与提醒效果。
- 群内有消息但没有提醒员工：优先检查员工是否在群内，以及两边手机号是否完全一致。
- 页面提示 Webhook 无效：检查环境变量是否为企业微信官方域名下的完整 Webhook，重新保存并重启。
- 页面提示冷却中：等待提示秒数后再试，避免短时间重复推送。

## 安全要求

- Webhook 只能保存在 Sealos 密钥环境变量中。
- 不把真实 Webhook 放入代码、数据库普通配置、截图、群聊或操作日志。
- 怀疑泄露时立即删除旧机器人并重新创建，再更新 Sealos 密钥。
- 操作日志只记录员工编号、人数、结果和错误代码，不记录手机号或 Webhook。
