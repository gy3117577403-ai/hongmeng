# v1.34.188 — 成品仓数量与收发交互

成品仓原来的“数量”混用了待入、可发等含义，规格被截断，快递单号输入占用了主要操作空间。本版把收发清单改为全宽紧凑表格，明确显示待入库、在库数量、已出数量和本次处理，规格允许完整换行。

## 数量口径

- 待入库：生产转入后尚未确认接收的数量。
- 在库数量：当前实物库存，包含可发、留库、占用和隔离部分；可发小于在库时另行提示。
- 已出数量：同一来源货批的有效出库记录累计，不受当天筛选影响。退货单独记录，不改写原出库事实。
- 本次处理：本次入库或出库的操作量，不代表累计量。
- 主收发清单按来源货批去重，记录页面保留每次实际出库；历史结清与正式实物数量分开表达。

## 交互

移除日常收发界面的快递单号与待补单号入口，简化出库打印记录。保留历史物流数据。待入库行支持“入库并发货”和“仅入库”，在库行支持“发货”和“留库”。连续处理仍需明确确认，回车只保存数量，不触发出库。数量可点击查看明细；入库及出库时间按真实操作记录显示。

批量处理和出库批次按单位分别汇总，避免把套、件等不同单位直接相加。本次不新增数据库迁移，也不改变现有登录和访问策略。

## 验证

- PostgreSQL 成品仓集成测试 23 项通过，覆盖部分收发、留库、隔离、累计出库、跨日期、退货、撤销接收和历史物流数据保留。
- 本地单元套件 1212 项通过，199 项数据库依赖用例在单元运行中跳过，失败 0。
- 隔离 PostgreSQL/MinIO 环境中的 HTTP 收发验收 72 项通过。
- 1366 × 1024 实际浏览器验收：一屏 24 行，规格完整换行；走通部分入库、部分发货、批量入库、急单入库并发货、留库/解除留库、数量草稿和连续处理；控制台无错误。
- 生产构建和类型检查通过。镜像发布由仓库工作流执行，并验证杭州匿名拉取与独立干净运行环境。
