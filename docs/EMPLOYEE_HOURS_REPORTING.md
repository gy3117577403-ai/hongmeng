# 员工工时与达成口径（v1.34.144）

普通扫码报工保存后直接形成本人实际生产日期的完成工时，不等待审批或前序数量覆盖。前序覆盖只处理生产数量关系，不再次增加已经记入的工时。重复提交不重复计入，撤回冲销原记录对应的个人工时。

## 统一口径

- 总出勤 A = 已确认正常出勤 + 已确认实际加班。底层考勤 actualMilliseconds 已含加班，汇总时不再加一遍；正常出勤由总出勤减实际加班展示。
- 完成工时 C = 原生产日期下有效、计入绩效的个人标准工时。前序尚未覆盖、当天考勤未完善，均不把该工时转入“待匹配”或从完成数扣除。
- 损耗 L = 当前员工原生产日期下已确认认可的异常工时；未确认异常仍按原异常流程处理。
- 达成率 = (C + L × 0.95) / A。个人目标系数不再改变此公式；超过 100% 正常显示，不封顶。
- 日、周、月、自定义区间均先汇总分子与分母，再相除，不平均每日百分比。汇总卡片、员工行、个人矩阵、班组和导出使用同一事实服务。
- A 为零或应有考勤尚未确认时显示“—”并提示考勤待完善，仍保留 C。未来日期不提前进入统计。
- 保留已有样品、不参与达成及历史资格快照规则；部分日期不参与时展示实际计入达成的分子、出勤基数。工序明确“不计绩效”的明细显示记录工时及“可计入完成工时 0”，避免明细与合计无法对账。

例：正常出勤 8 小时、加班 2 小时、完成 8 小时、已确认损耗 1 小时，达成率为 (8 + 1 × 0.95) / 10 = 89.5%。两天总出勤 15 小时、总完成 14 小时、总损耗 1 小时，周期达成率为 99.67%。

## 页面与报工资料

员工工时主表显示正常出勤、加班、总出勤、完成工时、已确认损耗和达成率，并提供日、周、月和自定义范围。旧“员工每日达成”页面使用同一报表组件；原待匹配链接重定向到员工工时达成。

取消独立“报工待处理”菜单。数量换算、来源或标准确实不足的特殊申报，保留在扫码及生产页面的“报工资料核对”弹窗中，旧链接继续打开原申报。标准缺失时保留真实数量、人员和日期，无法量化的数值不伪造；有效标准发布后，同口径记录可由既有恢复 worker 自动续接。异常工时确认、原有登录/操作权限与撤回审计继续有效。

按批分笔入账、准备工时、历史旧池及受控补账见 [按批工时说明](BATCH_LABOR_RECONCILIATION.md)。数据库迁移不批量重写旧结算记录；发布镜像也不执行正式库历史补账。

## 可复验项

- `employee-hours-report-integration`：日事实与 operations 同源、缺考勤保留完成、休息日、历史资格、非绩效明细、未来日期、已确认损耗和撤回。
- `batch-labor-proportional-integration`、`process-report-submissions-integration`：跨日比例分摊、重试、撤回、旧池、标准缺失和自动续接。
- `qa-employee-hours-release-runtime.ps1`：固定摘要镜像分别在两套独立 PostgreSQL/MinIO 空库启动、迁移和 bootstrap 改密。
- `smoke-employee-hours.mjs`：真实 HTTP 读取与扫码员工提交，管理端核对日/周/月、矩阵和撤回。
- `qa-employee-hours-export.ts`：读取隔离 API，使用页面的工作簿及明细 helper，写出日/周/月 XLSX 并重读核对；此脚本不代替浏览器下载落盘验证。

验收只操作明确命名的本机隔离数据库和测试员工，不访问正式业务数据库。镜像发布、隔离运行验证和 Sealos 正式切换分别记录。
