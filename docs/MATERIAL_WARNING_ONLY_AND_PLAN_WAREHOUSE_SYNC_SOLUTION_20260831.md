# 物料仅提示与半成品仓跨周排程方案

> 日期：2026-08-31
>
> 版本：v1.34.82
>
> 范围：计划中心、生产执行、半成品仓、二维码报工、周计划达成率、产能统计
>
> 发布边界：本文对应代码与迁移；镜像发布不等于正式生产/Sealos 切换

## 1. 前提纠正与最终规则

此前方案把“未配料时由计划开启允许开工”作为门禁，该规则已被本次需求取代，不能继续保留两套相互矛盾的开工条件。最终规则只有一套：

1. 未配料、待配料、缺料、数量不足、料不齐、料错等物料状态都只是仓库风险和跟进信息。
2. 上述物料状态不阻止计划下达、自动开工、人工开工、二维码访问或二维码报工，也不自动冻结订单。
3. 旧 `materialExecutionAllowed` 等字段只保留历史审计；读取时固定返回“不需要授权、执行允许”，旧写接口返回 `410 MATERIAL_EXECUTION_POLICY_RETIRED`。
4. 人工暂停和独立的非 MATERIAL 生产/质量硬控制仍然阻止生产，二者不得被“物料仅提示”规则绕过。
5. 已发生的报工、人员、工时、工作日期和数量流转是事实，不因转入半成品仓或改排而改写。

## 2. 半成品仓业务边界

半成品仓不是实际仓库配料任务的替代品，而是“已开始或等待继续生产的产品批次及其剩余工序计划”的独立台账。

- 可操作人：管理员、计划、生产主管、组长/班组长。
- 可选来源：本周、历史周和未来周的已下达产品批次；操作可以在周内任意时间发生。
- 可入仓状态：工艺路线已确认或生产中，且产品尚未全部完工。
- 半成品：至少一道工序已有合格报工，剩余工序未完成。
- 待生产品：尚无完成工序，但因排程调整需要从原周移出；与半成品使用同一仓台账，类型单独标识。
- 转仓数量不得超过 `计划批次数量 - 已完工数量 - 已存在开放半成品批次数量`。
- 每个批次保存来源周、工艺版本、已完成工序快照、下一工序、剩余工序、标准工时快照、物料警告、容器码/库位和操作原因。

## 3. 数量与工时守恒

### 3.1 入仓

入仓时只移动未完成部分的计划，不迁移或重写已发生事实：

```text
原周动态计划工时
= 原周原生计划工时
- 转入半成品仓时冻结的剩余标准工时快照

未排周半成品计划工时 = 0（不属于任何周）
```

每个剩余工序保存入仓时的数量和标准工时快照。该快照是来源周扣减依据，后续报工不会令来源周计划工时反向增加。

### 3.2 排周

半成品可以一次全部或分批排入本周或未来 11 周，并可选择生产班组：

```text
目标周动态计划工时
= 该周原生计划工时
+ 排入该周的半成品剩余标准工时
```

没有排入任何周的数量和工时不进入周计划、产能负荷和计划达成率分母。

### 3.3 改排

改排只处理原分配中尚未完成的数量和工时：

- 原周保留已报工数量和已实现标准工时。
- 原分配标记为 `SUPERSEDED`，其已完成部分仍计入原目标周。
- 未完成数量及对应剩余工时生成新的目标周分配。
- 已作为改排依据的报工不能直接撤回；撤回预览返回依赖阻断，要求先核对/撤销后续改排，避免破坏数量守恒。

## 4. 周计划达成率

周计划只采用动态计划分母：

```text
动态计划工时 = 原生计划工时 - 来源周移出工时 + 本周有效半成品排入工时
达成率 = 本周已完成有效标准工时 / 动态计划工时
```

口径约束：

- 已转仓但未排周：不计入任何周。
- 来源周：只保留转仓前已经完成的工时事实，剩余计划工时从分母移出。
- 目标周：只在排入后计入分母；实际报工计入该目标周分子。
- 改排后的原目标周：保留改排前已完成部分，不保留未完成部分。
- 无有效动态计划工时时，达成率返回空值而不是伪造 0% 或 100%。
- 缺失正式标准工时的工序禁止转仓，避免用估算值污染跨周指标。

## 5. 二维码报工

产品继续使用原产品二维码，不因进入半成品仓生成第二套报工身份。

1. 二维码票据返回当前有效的半成品周分配选项，包括批次号、容器码、目标周、数量和各工序剩余数量。
2. 普通未转仓数量仍按原工单可报数量报工。
3. 当报工数量涉及半成品库存时，只允许使用“报工日期所在周”的有效分配。
4. 同产品同周只有一个可用半成品分配时可以自动归集；存在多个批次时必须选择分配/容器，禁止系统猜测。
5. 报工事务同时写入 `ProcessCompletion` 和 `ProcessWipCredit`，并更新分配步骤、周分配和半成品批次状态。
6. 报工撤回同步作废 `ProcessWipCredit` 并重算数量/工时；已经发生后续改排时安全阻断直接撤回。

## 6. 数据模型与审计

新增表：

- `semi_finished_lots`：半成品/待生产批次主台账。
- `semi_finished_lot_steps`：入仓时剩余工序与标准工时快照。
- `wip_week_allocations`：目标周分配和改排链。
- `wip_week_allocation_steps`：分配到周的逐工序数量/工时。
- `process_wip_credits`：报工事实与半成品周分配之间的归属凭证。
- `wip_inventory_movements`：入仓、排周、改排等库存动作。
- `wip_events`：操作原因、前后快照和幂等事件。

所有写操作采用：

- PostgreSQL Serializable 事务。
- 主工单事务锁。
- 唯一幂等键。
- 数量、工时、日期范围数据库约束。
- `ProductionPlanChange` 与 `OperationLog` 双审计。

## 7. 页面与权限

新增 `/workspace/wip` 半成品仓模块，按 1366×1024 横屏平板设计：

- 顶部：批次数、总数量、未排数量、剩余工时。
- 左栏：任意周来源产品列表，可预览并转仓。
- 中栏：半成品批次列表及来源周、状态、排程进度。
- 右栏：剩余工序、目标周、班组、分批排程和改排。
- 计划中心产品行和跨周遗留行提供“转半成品”入口。
- 生产执行中心显示“本周动态计划达成率”和未排半成品排除说明。

查看继续复用计划/生产数据访问；变更计划只允许以下身份：

- `ADMIN` / `ADMIN_GLOBAL`
- `PLANNING_COLLABORATOR`
- `WORKSHOP_SUPERVISOR`
- `WORKSHOP_TEAM_LEADER`
- 兼容的 `TEAM_LEAD`、日排程主管/组长身份

现场报工人员只有二维码报工权限时，不能执行转仓、排周或改排。
