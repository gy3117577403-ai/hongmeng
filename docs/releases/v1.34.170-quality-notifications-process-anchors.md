# v1.34.170 工序发布与质量消息提醒

工序发布在删除被补报任务引用的工序时，完整检查补报插入位置、历史报工、执行与变更记录。有关联的工序保留为退役记录。继续有效的补报任务跟随新路线调整位置，已完成或已取消的任务保留原关联；不会创建虚假报工、重复补报义务或清除既有工时。

质量派单消息显示责任人、事件名称、去重后的产品、截止日期和站内短链接。集中分配给同一个人的待接单消息默认等待 120 秒合并；可通过 `QUALITY_NOTIFICATION_MERGE_SECONDS` 设置 0–300 秒。退回和品质确认进入即时队列。发送前核对任务是否已接单、改派、取消或转入下一阶段。短信式原生 text 消息携带企业微信原生提及参数。

优先采用管理员与通讯录核对过的企业微信成员 UserID。没有核实的 UserID 时使用员工手机号，旧档案里的 UserID 不会未经核对自动启用。通知记录展示接收账号、员工、脱敏目标、提醒方式、消息内容、发送批次及接口结果。接口已接收、群内确认和员工接单分别记录。

从异常详情的“通知与处理记录”进入“查看提醒设置与人员绑定”，或在原系统设置的企业微信页中选择员工，核对登录账号和提醒身份。管理员可保存身份、主动试发，再手动登记群内是否正确出现 @。变更提醒身份或机器人配置后，旧的群内验证结果自动失效。修改身份不会自动发送测试消息。

明确失败可自动重试；超时、无效回执或发送进程中断记录为“回执未确认”，由管理员核对群消息后选择是否重发。旧消息缺少发送目标快照时如实展示，不回填猜测的历史目标。

短链接必须登录，只解析为站内任务或品质确认页面，不授予其他人的处理权限。批量入口按当前账号加载对应记录，包含不在最近 300 条列表中的相关任务。

验证覆盖：真实 PostgreSQL 连续工序发布、补报锚点删除/尾部删除/同时删除、部分和已完成补报、重复发布、工时与数量不变；企微发送协议、精确账号映射、同名员工、合并窗口、过期提醒、短链接隔离和不确定回执；设置接口权限与冲突检查；平板和手机浏览器。传输协议使用隔离模拟接收器，实际群内 @ 需在已配置的真实群中由管理员试发并核对。
