# v1.34.130 重大异常协同工作台

把重大异常从重复标题、固定三栏和笼统的“协同中”，改为紧凑的异常队列与处理详情。新建工单、责任任务、品质确认、关联对象、归档弹窗、现场警示及工单附页使用一致的控件、操作反馈和橙色视觉层次。保留原有独立确认、重大审批、归档版本及生产放行规则。

## 业务与交互

- 异常标题可以编辑，空标题按问题事实生成；旧分类标题显示具体问题摘要，原始历史不改写。
- 服务端按有效任务投影草稿、待接单、处理中、待汇总、待品质确认、待归档、已归档。取消任务不计入完成数；无有效任务不能提交确认。
- 列表、我的任务和品质确认使用相同等待对象与阶段口径。品质通过后不再计入“待我确认”，仍需按归档要求完成归档。
- 新建表单按事实、影响对象、责任分工、时间证据分区，原因和方案在处理阶段填写。关联产品与具体工单分别选择，发布持续产品警示前说明影响范围。
- 新增公共任务截止日、增补任务截止日、待处理任务期限调整及原因留痕。任务提交后不再计为逾期。
- 任务接单、个人结果、牵头汇总、独立确认、定向退回和版本冲突均提供阶段反馈；定向退回保留其他责任人的已完成结果。
- 文字草稿按账号、异常、任务及轮次保留在当前标签页，12 小时过期。后台刷新保留输入；服务器正文变化时可选用服务器内容或保留本地输入。关闭新建窗口提示草稿和未上传文件的不同保留方式。
- 附件上传显示进度；部分失败保留草稿和失败文件，可继续重试，不提前分派。事件和任务的图片、PDF 使用共用预览器，支持居中、缩放与旋转。
- 异常队列服务端分页，每页 100 项，保留查询与滚动位置。通知深链可定位较早事件；责任人刷新使用其任务范围接口，不依赖质量管理读取权限。
- 已提交检验记录可发起异常，保存来源编号、版本、工单和问题摘要快照。检验记录仍属于原订单批次，来源后续编辑不覆盖异常中的快照。
- 协同说明写入事件流转记录，不代替正式处理结果。通知已投递、任务已接单、归档、警示生效分别展示。

## 数据与发布

迁移 `202609060004_quality_collaboration_source` 只向 `quality_risk_reports` 增加可空 `quality_source` JSONB。旧记录无需回填、删除或自动改变审批状态；“待汇总”是查询投影，不新增数据库审批状态。现场警示的发布/撤销、历史打印、普通员工报工和工艺修改后的完工核销沿用前版行为。

本地通过 TypeScript、Lint（保留项目既有图片优化提示）、1119 项单元测试；124 项数据库测试按默认规则跳过。另在单独 PostgreSQL 中通过质量 V1/V2/V3 与新阶段筛选回归，覆盖 35 组状态与任务组合、无有效任务、交接、定向退回、轮次冻结及审批权限。隔离应用通过 40 次真实 HTTP 检查，完成创建、来源约束、权限、截止日期、并发版本、多人处理、两轮品质确认、归档、工单同步、扫码警示与撤销。

发布流水线增加真实镜像浏览器验收：平板/手机、新建草稿恢复、上传失败重试、角色任务、冲突保留、定向退回、品质确认、归档影响预览、A4附页和现场扫码。国内镜像必须匿名完整拉取、核对摘要与 linux/amd64，在空 PostgreSQL/MinIO 中完成迁移、账号及业务验收。截图和结果作为 CI 附件保留；发布后交付实际通过记录和固定摘要。

镜像发布与 Sealos 切换分开。本次不切换线上镜像、不修改正式业务数据、不试发真实企业微信消息。
