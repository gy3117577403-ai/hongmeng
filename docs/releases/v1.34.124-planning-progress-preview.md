# v1.34.124 计划导入、报工核销与资料预览

## 变更

- 量产计划 Excel 改为 13 列：删除可见的来源订单号和订单行号，增加选填的单件计划工时（分钟）。支持 0.001–1440 分钟、最多三位小数；留空按已发布产品工时、原订单工时、待维护依次处理。计划工时保存在订单/批次和导入审计中，不改正式工序标准与既有计工。
- 内部订单标识根据上传文件、目标周和行号生成。同文件同周可安全重试；业务内容相同的两行仍作为独立订单并提示核对。旧版来源订单/行号模板继续支持。跨周追加需要选择原订单，并检查原订单剩余未排数量。
- 工艺发布、工艺变更和补充工序完成后，若已有普通报工等待核销且上游数量到位，沿原报工记录完成数量核销和成品流转。不会新增普通报工或重复计工。
- 后台每轮最多处理 3 个满足条件的历史路线，使用事务及版本/数量条件保护；跳过暂停工单、动作数量、返工分支、未完成补充义务及待处理不良。恢复情况写入路线活动与操作日志。可通过 `PROCESS_PENDING_COVERAGE_RECOVERY_ENABLED=false` 关闭该项恢复。
- 生产执行页分别显示工序数量进度和已计标准工时，并提供未完成原因及报工明细入口。工时达到 100% 时仍以实际工序、核销与分支状态判断完工。
- PDF 完成离屏渲染后，在同次绘制中切换位图及缩放；统一适配留边，避免额外滚动。翻页期间有明确提示。工序与工时资料弹窗保留同一文件、页码与缩放，更新资料列表时保持文件身份一致，分类/文件切换沿用方向未保存提醒。

## 验证与边界

- 新增导入工时与数量进度单元测试，以及真实报工→发布工艺→数量核销、历史恢复、幂等与暂停保护的 PostgreSQL 集成场景。
- 下载真实 Excel 并经 HTTP 预检、提交和重复提交；核对数据库接口返回的批次单件/总工时，覆盖旧模板、跨周关联、超量拦截和正式工时保护。
- 本地浏览器在 1366×1024 下检查导入预览、图片/PDF、翻页、旋转、缩放、全屏与延迟资料更新；证据保存在本次发布输出目录。
- 发布流水线检查镜像版本/提交、运行真实镜像的核销接口，并在国内镜像匿名完整拉取后的独立 PostgreSQL/MinIO 环境再次运行导入验收。
- 正式环境只进行了只读问题核查。镜像发布与 Sealos 切换分别处理；这份变更不代表已切换线上应用或已恢复线上工单。
