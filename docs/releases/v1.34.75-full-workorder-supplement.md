# v1.34.75 未完成工单新增工序整单补报

`v1.34.75` 取代未成功发布镜像的 `v1.34.74`，保留原有整单补报业务规则，并修复发布验收中发现的数据库时区兼容与工作流结果提示问题。

## 业务规则

- 未开工工单：新增工序进入正常工艺路线，按工单有效目标数量执行。
- 已开工但尚未完成的工单：每一道新增工序建立独立的整单补报义务，可报数量等于工单有效目标数量。
- 已完成工单：保持历史冻结，不自动重开；如确需返工，应走独立召回/返工流程。
- 补报义务只记录真实报工和真实工时，不生成普通物料投入，不重复向后序释放数量，也不增加成品数量。

## 610 类历史数据修复

镜像启动执行 Prisma 迁移时，会将旧版本中仍处于在制、尚未闭环，且被 `AUTO_BY_PROGRESS`、`FUTURE_ONLY` 或 `RECALL_REWORK` 处理的产品工时新增工序，统一重置为 `FULL_WORK_ORDER_REQUIRED`：

- `requiredQty = 工单有效目标数量`
- `systemCoveredQty = 0`
- `actualRequiredQty = requiredQty`
- `fulfillmentMode = ACTUAL`
- `remainingQty = max(0, requiredQty - 已有真实报工数量)`

迁移只处理同时满足以下安全条件的记录：来源部署已生效、工单与路线未完成、补报展示工序未退役、物料数量五项均为零、没有有效物料流转、真实报工汇总与义务台账完全一致。存在账实不一致的记录会保留原状，避免静默修坏。

每条成功重算都会写入 `process_route_activities` 与 `operation_logs`，并明确记录报工、物料流转、成品数量和工时记录增量均为零。迁移可重复执行；已重算记录不会再次改版本或重复写审计。

## 报工入口与显示

- 生产执行中心识别 `SUPPLEMENTAL_OBLIGATION` 后调用补报服务，不再误走普通转序接口。
- 报工界面显示整单目标、累计实报和剩余可报，并提示“不重复转序”。
- 流程中心同时展示“报工义务账”和“物料核销账”，避免把物料投入 `0` 误解为不可报数量 `0`。

## 本次发布修正

- 将重复工序集成验收更新为整单实报语义：系统覆盖数量为 `0`，实际应报数量为工单全套目标数量。
- 新增 UTC 安全迁移，修正非 UTC PostgreSQL 会话下旧企业微信通知记录“立即可重试”被错误延后约八小时的问题。
- 只有 GHCR 推送步骤实际成功后，工作流才会记录 Sealos 镜像源不可用提示，避免把发布前失败误报为镜像已发布。

## 验收不变量

- 新增补报工序的普通物料字段保持 `0`。
- 补报完成前后，普通物料流转记录增量为 `0`。
- 补报完成前后，工单成品完成数量增量为 `0`。
- 只有真实补报提交才创建 `ProcessCompletion` 和对应工时记录。
- 已存在的真实补报、参与员工和工时记录在历史重算中保持不变。
