# v1.34.159 — 修复普通异常告知单缺少二维码

普通异常告知单此前只显示扫码提示，没有二维码：页脚隐藏了普通异常的二维码容器，二维码准备过程也只处理有重大异常版本链接的记录。

- 每张普通异常告知页（含续页）现在生成并打印本工单查看码。扫码进入对应工单的现场页面，未登录时先使用员工账号登录，再返回该工单查看当前生效的异常及照片。
- 单独补打异常告知时也独立生成二维码，无需同时打印流转单。
- 二维码缓存按打印记录及警示共同区分；同一图纸异常在多张工单中批量打印时，不会串用最后一张工单的二维码。
- PDF 导出等待普通异常二维码准备完成；打印码保留四个模块的空白边缘。
- A 级异常继续使用原有归档版本查看链接，草稿预览规则保留。历史打印记录重新导出时也会补上二维码；已经下载或打印的旧文件需要重新导出/补打。
- 无数据库结构迁移，无生产数据修正。

验证：27 项相关单元与打印布局测试、TypeScript 检查通过；实际导出历史记录 3 页、仅异常告知 2 页、多工单批量 4 页，9 页均从 PDF 渲染图像中解码成功，并完成扫码后登录、返回工单与查看原图的浏览器验收。发布后继续执行固定镜像、杭州匿名拉取、全新 PostgreSQL/MinIO 启动与镜像内 PDF 解码验收。
