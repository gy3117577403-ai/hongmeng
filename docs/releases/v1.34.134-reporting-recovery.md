# v1.34.134 报工恢复与账户待办

解决工序修改后动作口径与工时标准混用、半成品旧周来源不可选，以及报工结果丢失后重复提交的问题。增加可追踪的报工申报与处理页；责任人核对后执行原报工，实际数量核销和工时入账成功才完成待办。确认使用结构化选项和数值，审计说明由系统生成，不要求输入自由文字。

## 业务行为

- 产品工时发布、工艺改时及撤回后的同步使用完整计量合同。已撤回、已作废的报工和工时池不会单独锁住旧口径；有有效动作历史时不自动换算成另一套计量口径。
- 工艺改时的动作工时预览及历史重算按实际动作计算，避免再乘一次每套动作数。删除其他工序但保留本工序完整标准时，既有工时池的历史标准、版本和金额保持不变。
- 电脑与手机保留账号、工单、具体工序和来源范围内的草稿。已点击提交但尚未得到确定结果的请求保留固定编号和原始内容，联网后按原编号核对，未提交的草稿不会自动报工。
- 手机始终展示来源及余额。普通来源剩余为零时不可选；旧周、未排、未来周仍可见并标注待确认，多批次不得猜测。两端默认真实当天，不把旧周半成品报工自动倒填到上周末。
- 历史作业补报可由有权责任人明确勾选确认本次真实日期，只核销所选有效来源的本次数量；不把剩余计划倒排，员工工时归实际作业日期，计划完成量仍归所选排程。须确认半成品在该作业日期已经存在。
- 普通报工、补充工序报工和对应扫码入口使用同一申报机制。明确可恢复的工时或来源问题可保存待处理；暂停、权限、原工序身份、超量等条件继续校验。
- 待处理记录保留原账号、实际作业人、生产日期、原始请求、工序版本与计量口径。可确定单位的申报占用可报余额；不能可靠换算的申报在核对前防止同工序重复申报。
- 数量尚未核销与数量已登记但工时待核定使用不同回执。待处理状态不等于完成；账号停用、二维码撤销、版本变化、数量变化等情况仍需重新核对。
- `/workspace/reporting-recovery` 支持账户范围列表、搜索、分页、原申报回看、结构化来源/数量/工时核对，以及取消尚未入账的申报。普通员工可看本人申报，处理操作按当前权限和任务分配复核。
- 工时和半成品问题同时出现时，处理页合并所需核对项，按权限交集匹配处理账号。处理账号失效后由既有后台任务轮巡转交有效账号，详情打开时也会重新核对。
- 账户消息直接进入对应申报。手动“标记完成”不能结束尚未解决的报工待办；成功后系统同步关闭待办并保留完成回执。重复确认只返回同一完工结果。

## 数据与升级

新增 Prisma 迁移 `202609070001_process_report_submissions`，增加申报账本、状态索引、原始快照和数量占用字段；`202609070002_process_reporting_source_snapshot` 保存每次完工选定的半成品来源，零整套动作报工也能准确重放。文件存储方式不变。迁移为增量，不批量改写已有生产事实；历史不一致在受控发布、工序同步或具体申报处理时修复。

部署前备份数据库。新版本已有未处理申报时，不应直接回退到不能识别这些数量占用的旧版本；先处理或取消未入账申报并核对数量。镜像发布与生产环境切换分别验收。
