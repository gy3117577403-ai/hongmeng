# v1.34.127 生产执行与工序协同修复

生产执行翻到第 60 条附近时，加载状态原来会触发 effect 清理，取消正在进行的下一页请求，随后重新发起，造成持续加载与闪屏。本版将请求生命周期与加载提示分开，失败保留已有列表并提供重试，刷新已加载范围时整批替换，保留滚动位置和选择。

## 修复范围

- 以 executionKey 区分普通工单和同一工单的不同半成品续作。PATCH 不再覆盖同源续作，较早发出的 GET 不能覆盖较新修改。
- 登录用户的生产查询生成十分钟有效的数据库查询快照，后续按索引范围读取任务，避免逐页重复整周汇总及排序变动导致漏项。快照按权限范围、周、筛选条件绑定，可跨应用副本使用。失效时提示刷新，不会用旧偏移量拼接新查询。
- 历史周普通批次数改为数据库 groupBy，移除读取前 5000 批的截断。
- 半成品续作按自己的数量、状态、完成时间及班组权限投影；已完成交期风险按实际完成日判断，日期缺失时标为待核实。
- 产品工艺发布及当前路线变更同步半成品剩余要求。被引用的工序保留为退役历史，取消其未完成要求；新增补充工序加入未完成续作；工时修订同步计划和已报工时。
- 普通与补充报工均支持明确选择半成品排程；撤回同步冲销工时归集，改排不重新生成已取消工序。并行及调整显示顺序后的完工核销依据剩余要求和已完成检查点。
- 原始报工与库存出入记录保留。删除工序仍执行既有的效率归集冲销规则，并同步半成品台账；不会通过伪造员工报工消除待办。

## 数据库与部署

新增迁移 `202609060003_production_execution_snapshots`，仅增加两张短期查询缓存表及索引。已有业务记录不需要手动清理。生产状态修复随工艺发布、报工、撤回及改排事务生效。

首次查询仍需计算当前范围的汇总；本版消除了后续翻页的重复全范围计算，不能据此认定任意数据规模下首次查询都无性能瓶颈。昂贵查询的进程内保护继续保留，已建立快照的续页使用有限范围的数据库读取。

镜像发布与 Sealos 切换分别验收。固定标签为 `ghcr.dockerproxy.net/gy3117577403-ai/hongmeng:v1.34.127`，部署时以成功发布后的实际摘要为准。
