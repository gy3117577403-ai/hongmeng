# v1.34.104 全系统响应优化

本版本按四个可回退批次处理产品工时、生产执行、计划中心、图纸/PDF、数据库和发布门禁。它解决了代码中已确认的结构性放大问题，但不能替代正式生产高峰的 P95/P99、锁等待、对象存储延迟和 WebView 实机验收。

## 第一批：产品工时读链路

- 产品工时列表从最多 800 款完整读取改为每页 50 款、最大 100 款的服务端分页。
- 列表 GET 不再执行计划周和图纸关联写式修复；相关维护继续由既有后台维护任务负责。
- 同一列表只保留一个在途请求，筛选会取消旧请求，读取 12 秒截止；仅 GET 的网络错误或 502/503/504 最多重试一次。
- 失败保留上次成功数据，首屏失败不再显示成“0 款产品”，错误卡显示请求追踪号。
- 图纸参考在打开面板后才加载；发布进度轮询在隐藏页面暂停、失败退避，并在 120 秒后停止自动轮询。

## 第二批：生产、计划和文件预览

- 生产执行首屏只读取 60 条；滚动至已加载数据末端时再取下一页，不再自动并发下载完整周。
- 计划中心筛选不再同时执行两次最多 5000 条的深关系计划查询；全局摘要和筛选结果复用同一份读取结果。
- 图纸资料 SSR 数据不再在组件挂载 260 毫秒后无条件重复加载。
- 图纸/PDF 认证代理支持 `HEAD`、单 Range、`206`、`416`、`Accept-Ranges`、`Content-Range` 和请求取消。
- S3 客户端改为进程内复用，避免每个对象操作重新建立客户端。

## 第三批：数据库和运行参数

- Prisma 数据源自动补齐可覆盖的连接池、池等待和连接超时参数；默认单实例连接上限为 10。
- 超过 `DB_SLOW_QUERY_MS` 的 Prisma 操作只记录模型、动作和耗时，不记录 SQL 参数或业务内容。
- 新增图纸、计划批次、计划订单和生产工单热点复合索引。
- 产品工时的工序字典与客户筛选项在浏览器会话内只读取一次；后续筛选和翻页不重复读取。
- 开启响应压缩，移除框架标识响应头，并优化 `lucide-react` 包导入。

## 第四批：验收与发布保护

- 单元测试新增请求超时/重试、HTTP Range、数据库连接参数和性能防回归契约。
- GitHub 镜像流水线将性能契约列为独立门禁，随后仍执行完整类型、Lint、单元、PostgreSQL 集成、镜像运行和国内镜像校验。
- 镜像版本统一为 `v1.34.104`。

## 上线前检查

1. 先确认 PostgreSQL `max_connections`；所有应用副本的 `DB_CONNECTION_LIMIT` 总和必须留出数据库管理、迁移和其他服务余量。
2. 新索引由 Prisma migration 创建。大数据量生产库应在维护窗口观察锁等待、磁盘余量和迁移时长，不能把测试库迁移速度当作生产证据。
3. 使用真实账号分别打开产品工时、生产执行、计划中心和图纸库，确认旧数据保留、分页续取和筛选结果一致。
4. 用普通 Chrome 与实际 WebView 检查 PDF Network：首段应为 `206`，切换文件时旧请求应停止。
5. 至少覆盖一个业务高峰，记录 `X-Request-Id`、`Server-Timing`、API P95/P99、5xx、数据库连接占用、慢操作日志、Pod CPU/RSS 和 S3 首字节。

## 建议验收门槛

| 指标 | 建议门槛 |
| --- | --- |
| 温实例页面壳 TTFB P95 | 不高于 1 秒 |
| 列表首批可用数据 P95 | 不高于 2 秒 |
| 轻量列表 API P95 | 不高于 800 毫秒 |
| API 非业务失败率 | 低于 0.5% |
| 网关或客户端超时率 | 低于 0.1% |
| 1366×1024 平板 INP P75 | 不高于 200 毫秒 |

未达到门槛时，先按追踪号和慢操作日志定位具体层级；不要直接延长超时或盲目增加 Pod。

## 回退边界

- 四批提交相互独立，可按逆序回退。
- 数据库索引为附加结构，不改变业务数据；应用回退后可以暂时保留。
- 如果新连接预算不适合当前副本数，优先通过环境变量降低 `DB_CONNECTION_LIMIT`，无需重建镜像。
- 本版本发布镜像不等于已切换 Sealos 或正式生产流量。
