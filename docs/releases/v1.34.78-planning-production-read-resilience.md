# v1.34.78 计划中心与生产执行加载修复

## 用户现象

- 计划中心提示“计划订单加载失败”，订单、排程和统计全部显示为 0 或空白。
- 生产执行与计划中心同时可能加载不出来。
- 部分历史计划已经存在有效计划批次和工单关联，但旧工单缺少 `plan_type`、`week_start_date`，因此不会进入对应生产周。

## 已核实根因

- 计划订单、生产执行和生产摘要的 GET 请求在读取前同步执行自动释放、跨周结转、工艺路线补齐等写事务；这些事务最长可占用 180 秒，并共享计划释放锁。计划批次集中切周或单个历史数据异常时，读请求会一起超时或返回 500。
- 前端把首次请求失败后的默认空状态当成真实业务结果，因而显示全 0、“暂无工单”或“订单池为空”，容易被误判为数据丢失。
- 一部分旧工单保留了有效的计划订单/批次关联，但没有同步新版本依赖的周计划元数据；只按工单字段过滤会漏掉这些工单。

## 修复内容

- 计划订单、生产执行和生产摘要 GET 改为只读请求，不再在用户刷新页面时执行长事务维护。
- 增加仅容器内部调用、令牌保护的计划维护周期；自动发布、自动启动和质量提醒投影使用非阻塞事务锁、有限批量与单项故障隔离，其余维护职责每轮只执行一个阶段并设置 4 秒硬超时，失败不会阻断页面读取。
- 系统自动维护使用空用户归属并保留明确的系统调度活动文本，不伪装成人工操作。
- 生产周查询增加保守兼容：只把有效、未软删除的计划订单与批次关联作为权威排产事实；支持直接工单及父/根分支工单。
- 本周兼容仅接受 `active` 批次，下周仅接受 `preparation` 批次，历史周严格按所选批次周；跨周遗留可接受仍有效且未完成的 `active`、`preparation` 或 `archived` 历史批次。无计划关联的旧工单不会仅凭日期进入生产执行。
- 计划中心和生产执行首次加载失败时用 `—` 与明确错误提示代替虚假 0/空态，并提供重试。
- 已有成功快照时刷新失败保留最近完整结果，标记最后成功时间；生产执行快照与完整查询键绑定，切周或修改筛选失败时不会把旧周工单显示成新范围的数据；自动刷新加入单飞控制和最长 5 分钟指数退避。
- API 返回稳定错误码、请求编号和无缓存响应头。产品/业务员辅助选项失败时保留上次成功选项并给出非阻断提示；周导航失败也不会拖垮主数据读取。

## 数据与发布边界

- 本版本没有数据迁移，不回填或改写报工、数量、工时、完成状态等生产事实。
- 历史兼容只读取已有有效计划关联；软删除工单、批次和计划订单均排除。
- 后台维护保留原有自动释放、跨周、图纸关联和工艺补齐职责，但从用户 GET 请求中移出。
- 自动启动与质量提醒投影采用后台最终一致处理；按默认 30 秒轮询和每次 2 项计算，61 项积压的理论完整扫描时间约 15 分钟，实际时间还取决于锁竞争与单项处理耗时。
- 未来周对齐、跨周结转、草稿工艺、图纸关联和历史删除数量仍沿用既有整阶段事务；阶段超过 4 秒会回滚并在后续轮次重试。本版本先保证读取可用性，不将这些后台职责宣称为已完成持久游标化。
- 本版本发布 `v1.34.78` 镜像；不自动切换 Sealos，不直接修改正式数据库。
