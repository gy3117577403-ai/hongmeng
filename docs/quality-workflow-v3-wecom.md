# 重大异常协同中心 V3 · 部署与企业微信接入

适用版本：v1.34.72（质量流程延续 v1.34.64，企业微信范围收窄）。镜像发布和 Sealos 切换是两个操作；发布镜像不会自动改动线上应用或正式数据库。

## 1. 本次业务流程

质量发起（事实、产品、多人责任分工） → 责任人分别接单/处理 → 牵头人汇总 → 独立品质确认 → 归档发布产品警示。

- 问题归属为工艺问题、品质问题、现场问题、物料问题；仅用于分流，不代替原因分析后的责任判断。
- 每个人有自己的责任任务，不能替其他责任人填写或提交。牵头人负责汇总，不意味着其他任务自动完成。
- 提交品质确认前，发生原因、根本原因、处理结论、具体解决方案必填，所有责任任务必须完成。流出原因等补充项仍可选填。
- 品质确认是独立页面 `/workspace/quality-confirmation`，仅指定的有品质权限账号可确认；不得同时承担同一事件的处理任务。
- 验证结果为空不能通过。退回需要理由和明确的责任任务，只有这些任务重新打开；此前结果、照片和其他人的完成状态保留。
- 每次提交形成独立轮次快照。第二轮不能自动沿用第一轮的验证结论。人员交接和重新投递均有审计记录。
- 原来的全局编辑按钮移除，草稿和各阶段信息从流程页面处理。照片按原比例预览；已有打印比例、自适应分页和员工只读扫码规则沿用。
- 已归档资料不被迁移重写。旧的未归档事件需在流程中确认分工后进入 V3。

## 2. 在 Sealos 更新应用

1. 先备份 PostgreSQL，保留当前镜像的精确版本/摘要和对象存储配置。
2. 使用交付说明中的 v1.34.72 镜像及不可变摘要，保持容器端口 **3000**。本次升级前必须停止旧实例及其通知 worker，再启动新镜像，避免旧版本在滚动升级重叠期继续发送工艺消息；请安排短暂维护窗口。
3. 保留原有 `DATABASE_URL`、`SESSION_SECRET`、S3 配置。不要为更新版本更换会话密钥，也不要更改原来的 bucket。
4. 不覆盖镜像启动命令；默认入口执行 Prisma 迁移、启动服务并运行通知队列。不要把生产容器改成 `next dev`。
5. 新增/核对下面两项环境变量。Webhook 应使用 Sealos 密钥/Secret 注入，仅服务端可读。

```dotenv
# 示例域名，必须替换为员工实际可以访问的正式 HTTPS 根地址。
APP_BASE_URL=https://your-app.example.com
# 完整群机器人地址。这里是占位示例，不要把真实 key 写进代码、截图或聊天。
WECOM_ROBOT_WEBHOOK_URL=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=REPLACE_WITH_REAL_SECRET
```

`APP_BASE_URL` 不含 `/workspace`、查询参数、账号或密码。`NEXT_PUBLIC_` 前缀不能用于 Webhook。不需要填写 CorpSecret 或 AgentId：当前交付是**群机器人消息推送**，不是自建应用单点登录。

默认通知轮询间隔为 30 秒，单次处理一条质量通知，另有数据库发送间隔保护；多人分派会依次发送，不是瞬时同时送达。v1.34.72 起仅质量异常的派单/交接、待汇总、待品质确认、退回、确认通过待归档允许自动外发。工艺变更及补充工序报工只保存站内通知；未知业务与事件默认禁止。不要为提高速度盲目调小轮询时间。

升级迁移会把旧工艺队列未发出的记录（包括重试耗尽、未来重试和发送中）重新排队。新 worker 在同一事务内补齐站内通知并标记外发 `CANCELLED`；旧的已发送记录不改写。新工艺记录的通道为 `IN_APP`，其 `SENT` 仅代表站内送达。不要清空共享 Webhook、关闭员工通知资格或停掉整个 worker：质量通知和补充工序闭环恢复仍需要保留。回退到旧镜像会恢复旧的外发逻辑，不能作为通知范围修复的安全回滚；应保留本版本的禁止外发逻辑后前向修复。已经发送的历史群消息不做撤回承诺。

6. 更新后确认新 Pod ready，再访问 `/api/health` 和 `/api/ready`，确认数据库和存储均正常。旧 Pod 未被替换时不要认为更新已经完成。
7. 首次打开系统设置的“企业微信”卡片刷新状态，确认 Webhook、HTTPS 回跳地址和队列启动配置。

## 3. 创建目标群机器人

在预期用于接收异常通知的企业微信内部群中，打开群管理，找到群机器人/消息推送入口，创建 Webhook 类型机器人并复制完整地址。客户端版本不同，入口名称可能有所差异。

企业微信官方现称该功能为“消息推送（原群机器人）”，创建完成后可取得专属 Webhook：[企业微信消息推送配置说明](https://developer.work.weixin.qq.com/document/path/91770)。腾讯云也提供创建、复制地址的参考步骤：[官方操作指南（PDF 中对应章节）](https://main.qcloudimg.com/raw/document/product/pdf/1551_84521_cn.pdf)。本次已核对官方文档中的文本消息、手机号提醒和每分钟 20 条限制，但未在用户实际群内验证客户端入口或机器人权限，以目标企业当前配置为准。

只把 Webhook 配到要接收这些问题的群，群成员都可能看到问题简介。如果简介包含不应向全群公开的信息，应调整该群成员范围或简介内容；处理详情仍需登录并校验事件权限。

## 4. 人事与系统账号映射

必须同时满足：

1. 责任人有可登录的真实系统账号，处于启用状态；不能只输入一个姓名。
2. 该账号绑定正确的人事员工记录，员工在职且启用。
3. 人事记录已填写有效手机号，且“通知”开关开启。
4. 该手机号对应企业微信通讯录中的同一个人，且此人在机器人所在群。
5. 品质确认账号需具备质量模块的流程执行权限。管理员在现有账号权限界面维护，不需要新建一套角色体系。

系统按账号关联的人事手机号生成 `text.mentioned_mobile_list`，不会因为姓名一样就自动合并，也不会静默退化成 `@所有人`。本版本对手机号使用大陆手机号码校验；不符合该格式的号码会显示等待配置。

## 5. 首次真实联调（需要由管理员明确试发）

1. 在系统设置 → 企业微信，选择 1 名已经在群内的测试人员。
2. 阅读消息预览，勾选“我确认发送真实测试消息”，点击发送。没有确认不会试发。
3. 在群里核对实际收到消息并正确 `@` 到该人。接口成功只表示企业微信接收请求，不能证明该人已读或接单。
4. 新建一份有明显“联调测试”说明的质量异常，选择两个不同责任人、一个牵头人及独立品质确认人。
5. 验证两位责任人收到自己的提醒，点击链接进入“我的质量任务”，接单并完成个人任务。
6. 牵头人补齐原因和方案后提交，品质确认人应收到独立页面链接；测试定向退回其中一人，再测试重新提交、验证通过、归档。
7. 检查关联产品的图纸警示、计划/执行提示以及工单附页预览。联调记录按正常回收规则处理，不要直接删数据库。

## 6. 通知行为与故障排查

| 状态 | 含义和处理方式 |
| --- | --- |
| 等待发送 | 业务已保存，通知已入持久队列；等待下一次轮询 |
| 等待配置 | Webhook、HTTPS 根地址、人事绑定、手机号或通知开关不满足；按具体提示修正 |
| 发送中 | 队列任务已被某个工作进程领取 |
| 企微已接收 | 企业微信返回成功；不等于准确 @、已读或已接单，请在群内实测 |
| 发送失败 | 网络、超时、限流或接口拒绝；按退避间隔重试，最多 8 次实际尝试 |
| 重试已用尽 | 修复原因后，质量管理人员在事件“企业微信通知与处理记录”中重新排队 |
| 过期通知已取消 | 任务已完成、改派、退回或轮次变化；不再发送旧接收人的过期提醒 |

缺配置不会回滚派单/处理结果。等待配置每分钟重新检查一次，不消耗实际发送重试次数。更改 Webhook 后要更新/重启对应 Pod。核对人事后可在事件内重新排队；发送前仍会检查事件是否过期。

采用至少一次投递：如果企业微信接收后网络断开，系统可能不知道已经送达，重试可能产生重复消息；请按消息中的通知编号核对。队列去重防止同一业务事件重复入队，但不宣称外部 HTTP 消息“恰好一次”。

链接打开后如未登录，需要登录本人账号，成功后保留事件/任务定位。群机器人不会自动赋予权限，也不提供企业微信免登录。普通车间员工查看已发布作业指引，继续使用原来的受限只读扫码页面；该入口与有写权限的责任处理链接不同。

## 7. 验收边界

本次开发可验证真实数据库、对象存储、权限边界、HTTP 接口和机器人请求协议。只有配置用户自己的 Webhook 并在实际群中完成试发后，才能确认真实群接入、手机号准确 @ 和员工手机网络可达。部署前后不要把测试请求、配置已保存、镜像已发布误写成“已上线且通知已送达”。

### 既有依赖安全风险（2026-08-28 检查）

通过 npm 官方 registry 执行 `npm audit --omit=dev`，当前锁文件仍报告 9 个生产依赖告警（2 严重、4 高、3 中），涉及既有 Next.js 14.2.15、jsPDF、SheetJS 等依赖。该结果是依赖公告匹配，不是已确认可利用路径或入侵证据。本次没有新增这些依赖，也没有把跨大版本依赖升级混入质量业务变更；功能镜像验收不代表全站安全验收。公开生产切换前应安排依赖升级与兼容性回归，不能将本次交付描述为“无安全告警”。
