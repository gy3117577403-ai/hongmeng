# 物品采购模块

入口：`/workspace/purchases`，系统导航「物料与仓储 → 物品采购」。本模块独立保存新采购业务，不迁移、不调用旧治具系统的数据。

## 初次使用

登录后进入采购工作台，打开「流程设置」，选择采购审批负责人、采购经办人、资金审批负责人、财务确认人及配置维护人。每个环节允许多人。所有已登录用户共享业务记录，写操作在服务端验证该环节的经办责任；申请修改、撤回限申请人或提交人。配置维护人和现有系统管理员可修改流程配置。

## 业务规则

- 一次申请可包含多项物品；明细可以分别批准、退回、修改重提。草稿保存到数据库。已批准明细不会被退回项的重新提交覆盖。
- 采购登记分别记录供应商、收款人、银行和账户。结算方式为对公现结、个人垫付、月结。单项实际采购总额达到 500 元需要合同编号，合同以版本快照留存。
- 采购登记与资金申请分开。对公资金单要求同供应商和收款账户；垫付报销允许同一垫付人的不同供应商合并；月结还要求相同账期。不同账户不合并。
- 申请金额有差额时须明确选择部分请款、优惠、运费或舍入，并说明原因。部分请款不会减少采购应付金额。金额以整数分保存，分摊尾差精确到分。
- 资金审批通过后，财务登记实际付款账户、发生日期和流水。允许分次付款，累计不得超过批准金额。已有未结束资金申请时，线下付款必须在原单登记，不能重复补录。
- 收货独立于付款。月结采购可先收货；收货记录进入具体仓库、库位和独立物资编号。物资台账支持领用、退库、盘盈盘亏及来源流水。
- 未入库退货不扣库存；已入库退货只可使用当前在库数量，已领用物品必须先退库。办理退货前，先撤回未付资金单；部分付款由财务关闭未付余额，已付事实保留。
- 供应商退款到个人账户时仍记为待归还，公司收到后才冲减净付款。正常票和红冲票分别保留，发票可按金额分摊到同一供应商的多项采购。
- 有效数量全部收货或取消、净付款等于应付、发票净额等于应付、退款全部回到公司后，明细自动进入已完成。
- 已产生资金、库存或票据事实的采购不能直接作废；未执行事项可带原因作废，记录和审计不删除。「全部采购 → 已作废记录」可查历史。

## 附件、合同和导出

支持 PDF、JPG、PNG、WebP，每份上限 20 MB，服务端校验文件头。上传内容直接存储到 S3 兼容存储，PostgreSQL 只记录元数据。预览和下载要求登录并返回短期签名地址。业务凭证追加留痕，不覆盖旧记录。

合同相同编号追加版本，历史版本保留当时的供需方、明细金额、交付和付款约定。打印和下载 PDF 是只读操作，不发起审批、请款或付款。PDF 使用浏览器排版生成，中文随页面字体呈现。

Excel 导出复用服务端筛选。勾选记录时导出选中项，否则导出全部符合当前条件的记录；超过 10000 条需要缩小范围。库存、资金单和采购明细分别使用对应列。

## 一致性与通知

所有写操作携带幂等键与业务版本。事务中的模块锁保护跨采购、资金和库存的批量操作；遇到旧版本必须刷新核对。付款、收货和库存还受数据库非负与余额约束保护。批量中任一项失败，整批回滚。

审批待办、退回、采购登记、资金审批和退款通过现有站内通知系统保存，事务提交后可查询。此版本不外发企业微信消息。

## 发布验收

- `tests/purchasing-domain.test.ts`：金额精度、付款分摊、资金分组和完成条件。
- `tests/purchasing-integration.test.ts`：PostgreSQL 中的部分审批、月结收货、分次付款、退货退款红冲、并发防重和状态冲突。
- `scripts/seed-purchasing-smoke.cjs`、`scripts/smoke-purchasing.mjs`：仅在明确标识的独立验收库创建账号，通过真实 HTTP 完成采购、S3 上传下载、资金、库存和 Excel 验收。
- 发布流水线对构建镜像和从杭州仓库匿名拉取的镜像分别运行采购验收。验收脚本不应指向正式业务库。

数据库变更仅新增 `Pc*` 表及其约束，不更改其他模块的历史表。部署沿用现有 PostgreSQL 和 S3 环境变量，镜像启动时执行 Prisma migration。
