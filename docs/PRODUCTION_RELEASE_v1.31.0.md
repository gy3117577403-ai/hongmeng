# v1.31.0 发布说明

候选镜像：`ghcr.io/gy3117577403-ai/hongmeng:v1.31.0`

本版本完成现场工艺变更与产品工序工时的统一同步：

- 修复自由输入新增工序错误继承插入锚点工序的问题。
- 工艺审核可明确绑定同名工序定义；员工说明和审核意见均可选填。
- 产品工序与工时发布前展示全量影响，发布后同步现有工单路线、原二维码、生产执行和流程中心。
- 已报工标准工时通过作废、反冲和替代记录追溯重算，不覆盖审计历史。
- 后序已有报工或工单已完成时，新增工序生成零物料流的补充报工义务；报完后工单重新完成。
- 保留稳定 `occurrenceKey`，支持同一道工序在同一路线多次出现。
- 提供旧版“新增名称被错误绑定为锚点工序”的只读审计和受控修复命令。

数据安全边界：跨已有数量事实的调序、仍有在途投入或数量台账的删除会在发布预览中阻断。这是数量闭环保护，不会创建质量、复检或人工审批流程。

部署前需核验 GitHub Actions 全绿、镜像 commit/digest、`linux/amd64` 架构、70 个 Prisma 迁移、容器 `/login` 和内部 outbox 端点。镜像发布不代表已切换正式生产；生产切换应固定不可变 digest 并单独执行。

旧错误绑定数据先执行只读审计：

```bash
npm run process-route-bindings:audit -- --json
```

确认输出后才执行受控修复：

```bash
npm run process-route-bindings:repair -- --json
```
